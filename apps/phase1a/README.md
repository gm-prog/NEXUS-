# NEXUS Phase 1A local deterministic demo

This project is an isolated, synthetic local demo for exactly four application services—`api-gateway`, `checkout-service`, `order-service`, and `payment-service`—plus `payco-mock` and an OpenTelemetry Collector. The mock is not an application service. Each service is a separate container/process with its own service identity and health endpoint. This is not an investigator, production system, durable telemetry platform, or Phase 1B implementation.

## Prerequisites and isolated environment

- Docker Engine and Docker Compose v2 for the complete multi-process demo.
- Python 3.11+ for the black-box smoke script.
- `uv` 0.13.0 for app lock verification/tests. The repository root lock and Phase 0 dependencies are unchanged.

From the repository root:

```bash
python -m pip install --only-binary=:all: --no-deps 'uv==0.13.0'  # tooling install, outside app venv
uv --project apps/phase1a lock --check
uv --project apps/phase1a sync --locked --group dev
apps/phase1a/.venv/bin/python -m pytest apps/phase1a/tests
```

The app owns `apps/phase1a/pyproject.toml` and `apps/phase1a/uv.lock`; no FastAPI, HTTPX, or OpenTelemetry dependency is added to `nexus-benchmarks`.

## Start, inspect, run, reset, and stop

Run commands from the repository root:

```bash
scripts/phase1a.sh validate
scripts/phase1a.sh up
scripts/phase1a.sh status
scripts/phase1a.sh run INC-001
scripts/phase1a.sh reset
scripts/phase1a.sh run INC-005
scripts/phase1a.sh reset
scripts/phase1a.sh run INC-006
scripts/phase1a.sh run all --repeat 2
scripts/phase1a.sh logs
scripts/phase1a.sh down
```

`scripts/phase1a.sh smoke` performs Compose validation by startup, runs all cases twice, checks OTLP signal output, and leaves the stack running for inspection. `down` removes the containers and network; there is no volume or durable telemetry store. Smoke execution uses bounded HTTP timeouts and virtual scenario timing, not long sleeps. The Collector output is ephemeral container stdout; inspect it with `scripts/phase1a.sh logs` and clear it with `down` followed by a fresh `up`.

The only host-published application port is `127.0.0.1:8000` for the gateway. Backend services and `payco-mock` have no host port. The Compose bridge is private to the project. Demo controls require `NEXUS_DEMO_MODE=true` and the local-only bearer value `local-demo-only`; these are synthetic defaults, not credentials. Do not reuse them outside this demo.

## HTTP routes

- `GET /health/live` and `GET /health/ready` on each service.
- `POST /api/v1/checkout` routes gateway → checkout. Normal and INC-001 flows call payment-service; INC-005 calls payco-mock directly.
- `POST /api/v1/orders` routes gateway → order-service.
- `POST /api/v1/payments` routes gateway → payment-service.
- `GET /__demo__/status`, `POST /__demo__/trigger/{INC-001|INC-005|INC-006}`, `POST /__demo__/reset`, and `POST /__demo__/simulate/inc-006` are demo-only gateway controls. All mutations require the local demo token.

No request bodies or billing values are logged. The only billing-related log attribute is `billing_address_present`.

## Telemetry

The services export OTLP gRPC to the pinned Collector on the private Compose network. The Collector enables traces, metrics, and logs pipelines and the `debug` exporter only. Its output is visible through `docker compose logs`; no remote exporter, file sink, database, or persistent volume is configured.

Service resources include `service.name`, `service.version`, and `deployment.environment.name=nexus-local-demo`. Log export uses a batch processor; scenario-critical records are explicitly force-flushed off the async event loop before their response, and provider shutdown flushes the remaining queue. Server middleware creates spans and bounded request-count/duration metrics. Explicit client spans inject W3C Trace Context on actual HTTP requests. Structured JSON logs carry `service.name` and active `trace_id`/`span_id`; request payloads are not logged. Synthetic percentage observations remain in `nexus.fixture.synthetic.rate_percent` (unit `%`); INC-005 virtual latency uses the separate `nexus.demo.synthetic.logical_latency` histogram (unit `ms`) and is recorded only when PayCo mock returns 504. Its 30,000 ms sample is logical, not elapsed wall time, and no success-rate denominator is inferred. For INC-006, the 95/3/2 model distribution is recorded only in `nexus.demo.synthetic.gateway.modeled_request_decisions` with explicit synthetic provenance; real gateway decisions are separately counted by `nexus.gateway.http.rate_limit.decisions` only on actual HTTP proxy requests. 429 and 5xx classifications are separate.

A complete proof run is:

```bash
scripts/phase1a.sh smoke
scripts/phase1a.sh logs
scripts/phase1a.sh down
```

Before any health/scenario traffic, the smoke runner captures a UTC cutoff and polls timestamped Collector output with Compose `logs --since`. It parses service resources inside each OTLP signal block and requires the explicit matrix: all five services for traces and metrics; `api-gateway`, `checkout-service`, `payment-service`, and `payco-mock` for logs. `order-service` intentionally emits no scenario business log. Missing, stale, or wrongly associated signal/service evidence fails the bounded poll.

## Reset and limitations

Reset clears the gateway rate-limit scenario and the payment/PayCo injected faults; the telemetry SDK's monotonic counters are not reset. Run deltas or start a fresh stack for a clean telemetry stream. The scenario response bodies and smoke assertions are deterministic, but the Collector's timestamps and trace IDs naturally vary. Docker/Compose behavior must be verified in an environment with Docker; a unit-test pass alone does not prove topology or Collector receipt. Phase 1B, all other fixtures, persistent stores, evaluation, production deployment, and diagnosis scoring remain out of scope.
